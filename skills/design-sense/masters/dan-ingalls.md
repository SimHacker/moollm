# Dan Ingalls

**Class:** master · **Head:** liveness; the language is the system

Smalltalk's implementor across every generation (-72, -76, -80, Squeak, Lively
Kernel), and the author of its design creed, "Design Principles Behind Smalltalk"
(Byte, 1981): "An operating system is a collection of things that don't fit into
a language. There shouldn't be one." Personal mastery: a system serves the
creative spirit only if it's entirely comprehensible to a single individual.
BitBlt: one primitive underneath all graphics, fast enough to make the
overlapping-windows illusion real. The lens he grinds: the system should be
alive all the way down — inspect it, change it, and it keeps running while you do.

## Votes

- **Keep the system alive all the way down** — inspect it, change it, and it keeps
  running while you do ([Design Principles Behind Smalltalk](https://www.cs.virginia.edu/~evans/cs655/readings/smalltalk.html);
  [everything-is-concrete](../methods/everything-is-concrete.md))
- **Fit the system in one head** — personal mastery: if a single motivated person
  can't comprehend the whole, the creative spirit has no purchase
  ([power-of-simplicity](../methods/power-of-simplicity.md))
- **Dissolve the operating system into the language** — everything the language
  can't reach is a wall someone will hit
  ([low-floor-no-ceiling](../methods/low-floor-no-ceiling.md) for substrates)
- **Find the one primitive under everything** — BitBlt beneath all graphics;
  uniform mechanism, endless surface
- **Rebuild it live, in public** — Squeak bootstrapped Smalltalk in Smalltalk;
  the Lively Kernel put the whole live system in a browser tab
  ([Squeak](https://squeak.org/) · [Lively Kernel](https://lively-kernel.org/))

## Vetoes

- Don't ship a system its user can't open while it runs
- Don't hide behavior in an "operating system" the language can't reach
- Don't let comprehensibility exceed one motivated head

# Methods

Part of [design-sense](../README.md) · [lenses/](../lenses/README.md) ·
[masters/](../masters/README.md) · [seeds/](../seeds/README.md)

A **method** is a way of working — a repeatable procedure or process constraint:
grow by accretion then tune, compress the design onto one page, measure the
time-to-penis before launch day measures it for you. Where
[lenses](../lenses/README.md) change what you notice, methods change what you do
next.

## Format

Same anatomy as lenses: header with attribution, one-line bold statement, body
with the protocol and its dividends, **Go deeper** external links, **Sources**
into the corpus, **See** for kin. Several are **dispatch pointers** to whole
moollm skills ([play-learn-lift](play-learn-lift.md),
[sister-script](sister-script.md), [melt-then-ladle](melt-then-ladle.md),
[procedural-rhetoric](procedural-rhetoric.md),
[advertisement-economy](advertisement-economy.md),
[everything-is-concrete](everything-is-concrete.md),
[worse-is-better](worse-is-better.md)) — the design-sense angle here, the full
protocol there.

## Choosing methods

[CARD.yml](CARD.yml) maps phases of work to method sets: growing a design,
designing a simulation, explaining, building substrates, governing communities,
shipping under pressure.

## Lens or method?

If it changes what you *see*, it's a lens. If it changes what you *do*, it's a
method. Some principles have both faces — the simulator effect is a lens; "don't
implement what implication supplies" is its method half, and lives in the same
file until the split earns its keep ([instance-first](instance-first.md) applies
to the registry itself).

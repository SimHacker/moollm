# Seeds

Part of [design-sense](../README.md) · [lenses/](../lenses/README.md) ·
[methods/](../methods/README.md) · [masters/](../masters/README.md)

Incoming harvest. A **seed** is a raw design principle — scouted from the
corpus or found in reading — that hasn't yet been grown into a
[lens](../lenses/README.md), [method](../methods/README.md), or
[master](../masters/README.md).

The name is a sinsemilla joke that earns its keep: seeds come in raw, get
grounded (literally — every seed must be traced to a corpus source before it
germinates), and cure into plugins. The batch files are the farm log, and the
log is the point: each dated file records what arrived, where it came from,
what it became, and what's still in the ground.

## Structure

One file per harvest batch, dated (`YYYY-MM-DD-source.md`), each with:

- **Planted ✅** — seeds that became plugins, each linking to the grown file
  (and noting merges: `attention-stays-on-pointer → merged into foveation`)
- **Todo 🌱** — still raw; the open germination queue

## Protocol

PLANT-SEED and GERMINATE live in [CARD.yml](CARD.yml); the full skill protocol
is [../SKILL.md](../SKILL.md); the longer farming journal is
[../CAULDRON.md](../CAULDRON.md). The discipline that matters: never write a
plugin from memory alone — ground the seed in a source first, so every
registry file's Sources section has somewhere real to point.

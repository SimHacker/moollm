# Three-Axis Accessibility

**Class:** lens · **Attribution:** moollm constitution §3

> **Humans read it. LLMs sniff it. Machines parse it.**

Every lasting representation now has three audiences, and formats that serve one
while starving the others accumulate debt. Humans need prose, narrative, and
visual scanning; LLMs need k-lineable names, semantic density, and comments that
carry intent; machines need parseable structure. YAML with meaningful comments
scores on all three; minified JSON scores on one; a screenshot of a table scores
on zero-point-five. The lens is a checklist applied at format-choosing time:
who *can't* read this, and what will that cost when they need to?

The design-sense payoff: this is why the registry you're reading is Markdown
with stable headings and links — humans browse it, LLMs activate on the names,
and tools can still walk the structure. Single-axis formats are sometimes right
(a database is for machines; a poem is for humans), but they should be a chosen
trade, not a default.

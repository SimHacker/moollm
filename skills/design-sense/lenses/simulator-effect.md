# Simulator Effect

**Class:** lens · **Attribution:** Will Wright (1996 Winograd talk tradition)
**Dispatch:** whole skill at moollm [skills/simulator-effect/](../../simulator-effect/) — load it; this entry is the design-sense pointer.

> **Implication beats simulation. Imagination is free compute.**

Games run on two computers: the tame, shallow simulation on the desk and the deep,
wild one in the player's head. Sparse local rules produce patterns players narrate
as causal stories the programmer never wired — SimCity players see corruption,
gentrification, and revenge in a cellular automaton that knows none of those words.
That imaginative fill-in is the medium, not a bug: the player's model of the game
is richer than the game, and the design goal is to *feed* that model, not correct it.

The discipline this buys: don't implement what implication supplies for free.
Over-specifying kills the richer mental model — "reverse over-engineering" is a
desired outcome. Every detail you render is a detail the player stops imagining.
Comics found the same law in the gutter between panels
([gutter-closure](gutter-closure.md)); Eno found it in generative music. Wright's
version simply runs at simulation scale.

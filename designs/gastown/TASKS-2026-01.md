# MOOLLM tasks, January 2026

The backlog from January 2026, moollm-001 through moollm-033, kept as a record and as an
example of the ledger layout described in [skills/task](../../skills/task/SKILL.md): one file,
one fenced YAML block per task, an index at the top.

These entries predate the task skill, so they store `status:` and `depends_on:` where the skill
now uses events and `requires` with guards, and most have no `done_when`. Read them as history,
not as a schema to copy. The current schema is in [skills/task/CARD.yml](../../skills/task/CARD.yml).

```yaml
id: moollm-033
title: "YAML Jazz vs JavaScript semantic richness"
status: done
priority: medium
completed: "2026-01-24"
source: "Session insight"

description: |
  Documented why MOOLLM tasks (YAML Jazz) are MUCH and MEANINGFULLY
  semantically richer than what JavaScript/JSON can express.
  
thesis: |
  JavaScript gives you data.
  YAML Jazz gives you DATA + MEANING + CONTEXT + REASONING.
  
what_javascript_cannot_express:
  comments_as_data: |
    JS:   { status: "pending", priority: "high" }
    YAML: status: pending
          priority: high
          # HIGH because user explicitly asked and blocks 3 tasks
          
    THE COMMENT IS THE REASONING. The LLM reads it.
    
  multiline_prose: |
    JS preserves nothing. Blob of text.
    YAML's | preserves formatting, line breaks, markdown.
    The prose breathes. The structure teaches.
    
  nested_reasoning: |
    JS: { task: "fix bug", notes: "..." }
    YAML: reasoning with hypothesis, investigation_order, inner_voice
    THE REASONING IS PRESERVED.
    
yaml_jazz_enables:
  - LLM-readable reasoning (comments are context)
  - Git-friendly diffs (semantic changes visible)
  - Human + LLM + machine readable (serves three audiences)
  - Extensibility without breaking (Postel's law)
  
vs_cursor_todos: |
  Cursor's internal todos: JavaScript objects
  - No comments (reasoning lost)
  - No context (just fields)
  - Ephemeral (lost on session end)
  
  MOOLLM tasks in git:
  - Comments ARE reasoning
  - Context travels with data
  - Immortal (version controlled forever)
  
empirical: |
  Sunil Kumar (Groundlight AI, 2025):
  "Switching from JSON to YAML massively improved entropy stability."
  JSON constrains. YAML gives room to breathe.
  
files_updated:
  - skills/yaml-jazz/CARD.yml
  - designs/gastown/TASK-ORCHESTRATION.yml
```
